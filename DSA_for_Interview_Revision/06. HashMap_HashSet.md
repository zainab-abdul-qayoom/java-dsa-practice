# HashMap & HashSet — Complete Interview Prep Notes

---

## 1. What is a HashMap? (Simplest Explanation)

A HashMap stores data as **key-value pairs** — think of it like a real dictionary: you look up a **key** (a word) to instantly get its **value** (the definition). Every key must be unique, but values can repeat.

```java
HashMap<String, Integer> ages = new HashMap<>();
ages.put("Zainab", 20);
ages.put("Ali", 22);

ages.get("Zainab");   // 20 — instantly retrieved using the key
```

**Why it's fast:** HashMap uses a technique called **hashing** — it runs your key through a formula (a "hash function") that converts it into a number, which tells Java exactly which internal "bucket" (slot) to store or look up that key-value pair in. This means lookups, insertions, and deletions are all close to instant on average — **O(1)** — instead of having to search through everything one by one.

---

## 2. What is a HashSet? (Simplest Explanation)

A HashSet stores a collection of **unique values only** — no key-value pairs, just values, and duplicates are automatically ignored.

```java
HashSet<Integer> numbers = new HashSet<>();
numbers.add(1);
numbers.add(2);
numbers.add(1);   // ignored — 1 is already in the set

System.out.println(numbers);  // [1, 2]
```

**Fun fact you can mention in an interview:** internally, a HashSet is actually built using a HashMap — every value you add is stored as a *key* in a hidden HashMap, with a dummy placeholder value. That's why HashSet gets the same fast O(1) performance as HashMap.

## 3. Core HashMap Methods (with Why/How)

```java
HashMap<String, Integer> map = new HashMap<>();

map.put("apple", 5);          // adds/updates the key "apple" with value 5
map.put("banana", 3);
map.put("apple", 10);          // "apple" already exists — this UPDATES its value to 10

map.get("apple");                // returns 10
map.get("mango");                 // returns null — key doesn't exist!

map.getOrDefault("mango", 0);      // returns 0 instead of null if key is missing (safer)

map.containsKey("apple");           // true
map.containsValue(10);               // true
map.remove("banana");                 // removes the key-value pair for "banana"

map.size();                            // number of key-value pairs
map.isEmpty();                          // true/false
map.keySet();                            // returns all keys as a Set
map.values();                              // returns all values as a Collection

// Looping through a HashMap — the most interview-relevant pattern
for (Map.Entry<String, Integer> entry : map.entrySet()) {
    System.out.println(entry.getKey() + " -> " + entry.getValue());
}
```

## 4. Core HashSet Methods

```java
HashSet<String> set = new HashSet<>();

set.add("apple");                // adds a value
set.add("apple");                 // ignored — duplicate
set.remove("apple");               // removes a value
set.contains("banana");             // true/false — O(1) lookup
set.size();                          // number of unique elements
set.isEmpty();                        // true/false

for (String item : set) {              // loop through (order is NOT guaranteed)
    System.out.println(item);
}
```

## 5. The Classic Use Case: Frequency Counting

This is the single most common pattern you'll use HashMap for in DSA problems — counting how many times each element appears.

```java
String word = "programming";
HashMap<Character, Integer> freq = new HashMap<>();

for (char c : word.toCharArray()) {
    freq.put(c, freq.getOrDefault(c, 0) + 1);
}
// freq now maps each character to how many times it appeared
```

**Why `getOrDefault` matters here:** without it, you'd have to first check `if (freq.containsKey(c))` before incrementing — `getOrDefault(c, 0)` cleanly handles "if this key doesn't exist yet, treat it as 0" in one line.

## 6. HashMap vs HashSet vs ArrayList — Side by Side

| | ArrayList | HashSet | HashMap |
|---|---|---|---|
| Stores | Ordered values, duplicates allowed | Unique values only | Key-value pairs, unique keys |
| Order preserved? | Yes (insertion order) | No | No |
| Lookup by value | O(n) — must search | O(1) — hashing | O(1) for keys — hashing |
| Best for | Ordered lists, indexed access | Checking uniqueness/membership fast | Fast lookup by a key, frequency counting |

## 7. Common Mistakes People Make

- Forgetting that `map.get(key)` returns `null` if the key doesn't exist — trying to use that null value directly (e.g. adding to it) causes a `NullPointerException`. Use `getOrDefault()` to avoid this.
- Assuming HashMap/HashSet preserve insertion order — they don't. If order matters, use `LinkedHashMap`/`LinkedHashSet` instead.
- Using a mutable object as a HashMap key and then changing it after inserting — this can break lookups, since the hash code may change and Java can no longer find it in the right bucket.
- Confusing `containsKey()` with `containsValue()` — the first checks keys (fast, O(1)), the second checks values (slow, O(n), since values aren't hashed).

## 8. Full Interview Q&A

**Q1: What is a HashMap and how does it achieve fast lookups?**
A: A HashMap stores key-value pairs. It uses a hash function to convert each key into a number that determines which internal "bucket" to store it in, allowing near-instant (O(1) average) insertion, lookup, and deletion instead of searching sequentially.

**Q2: What is a HashSet, and how is it related to HashMap?**
A: A HashSet stores unique values with no duplicates. Internally, it's implemented using a HashMap — each value is stored as a key, paired with a dummy placeholder value, which is why HashSet gets the same O(1) average performance as HashMap.

**Q3: What happens if you call `.get()` on a HashMap with a key that doesn't exist?**
A: It returns `null`. This can cause a NullPointerException if you try to use that result directly (e.g., incrementing it) without checking — use `getOrDefault(key, defaultValue)` to handle this safely.

**Q4: Does HashMap or HashSet preserve insertion order?**
A: No — neither guarantees any particular order. If insertion order needs to be preserved, use `LinkedHashMap` or `LinkedHashSet` instead.

**Q5: What is the time complexity of add/remove/contains operations on a HashSet?**
A: O(1) on average, due to hashing — though in rare worst-case scenarios (many hash collisions), it can degrade to O(n).

**Q6: How would you count the frequency of each character in a string using a HashMap?**
A: Loop through each character, and for each one use `freq.put(c, freq.getOrDefault(c, 0) + 1)` — this either initializes the count to 1 or increments the existing count.

**Q7: What's the difference between `containsKey()` and `containsValue()` in terms of performance?**
A: `containsKey()` is O(1) because keys are hashed for fast lookup. `containsValue()` is O(n) because values are not hashed — Java has to check every entry one by one.

**Q8: Why shouldn't you use a mutable object as a HashMap key?**
A: If the object's contents change after being used as a key, its hash code may change too, which can make the HashMap unable to find it anymore — effectively "losing" that entry even though it's technically still stored somewhere internally.

## 9. One-Minute Summary (say this out loud before an interview)

"HashMap stores key-value pairs and uses hashing to achieve O(1) average time for insertion, lookup, and deletion, by converting each key into a bucket location instead of searching sequentially. HashSet stores unique values only and is actually built internally using a HashMap with dummy values, giving it the same fast performance. Neither preserves insertion order — use LinkedHashMap/LinkedHashSet if that's needed. The most common real use case is frequency counting, typically done cleanly with `getOrDefault()` to avoid null checks."
