# Strings & StringBuilder — Complete Interview Prep Notes

---

## 1. What is a String? (Simplest explanation)

A String is text — a sequence of characters, like `"hello"`. In Java, String is technically an **object**, not a primitive type, even though it feels like one because you can write `String s = "hello";` without `new`.

---

## 2. Why is String Immutable? (The Full Simple Explanation)

**Immutable = cannot be changed once created.** Once you make a String, its value inside memory never changes — any "change" actually creates a brand new String object.

**Why did Java design it this way?**

Java keeps a special memory area called the **String Pool** (also called String Constant Pool). When you create a String using double quotes (not `new`), Java checks: "Do I already have this exact value stored somewhere?" If yes, it reuses that same object instead of making a new one — saving memory.

```java
String a = "hello";
String b = "hello";
// Both a and b point to the SAME object in the pool — memory saved!
```

If Strings were mutable (changeable), and you changed `a` to `"world"`, then `b` would accidentally become `"world"` too, since they share the same object. That would be chaos. So Java makes String immutable specifically to make this memory-sharing trick safe.

**What actually happens when you do `str = str + "abc"`?**
Java does NOT change the original String. It:
1. Creates a brand new String object with the combined value
2. Points your variable `str` to this new object
3. The old object is left behind (eventually cleaned up by Java's garbage collector)

This is exactly why doing this repeatedly inside a loop is wasteful — a new object is created every single time.

## 3. `==` vs `.equals()` — The Most Asked String Question

| | What it checks | Example |
|---|---|---|
| `==` | Are both variables pointing to the exact same object in memory? | `a == b` |
| `.equals()` | Do the actual characters/values match? | `a.equals(b)` |

```java
String a = new String("hi");
String b = new String("hi");

System.out.println(a == b);        // false — two DIFFERENT objects (because of "new")
System.out.println(a.equals(b));   // true — same characters inside
```

But if you don't use `new`:
```java
String x = "hi";
String y = "hi";
System.out.println(x == y);        // true — both point to the SAME pooled object
```

**The safe rule to always follow:** Never use `==` to compare String values. Always use `.equals()`. `==` becomes unreliable the moment `new` is involved, and interviewers love asking about this exact trap.

## 4. Common String Methods (with what they actually do)

```java
String s = "Hello World";

s.length()             // 11 — number of characters
s.charAt(1)             // 'e' — character at index 1
s.substring(0, 5)        // "Hello" — from index 0 up to (not including) index 5
s.equals("hello world")  // false — case-sensitive comparison
s.equalsIgnoreCase("hello world")  // true — ignores case
s.split(" ")             // ["Hello", "World"] — breaks into an array
s.toCharArray()          // ['H','e','l','l','o',...] — converts to char array
s.trim()                 // removes extra spaces from start/end
s.toUpperCase()          // "HELLO WORLD"
s.toLowerCase()          // "hello world"
s.indexOf("World")       // 6 — position where "World" starts
s.contains("World")      // true
s.replace("World", "Java")  // "Hello Java"
```

## 5. Why StringBuilder Exists

Since String can never change once created, building a String piece-by-piece inside a loop using `+` means Java creates a **new object every single loop iteration** — wasted memory and wasted time.

**StringBuilder solves this because it is mutable.** It has one object in memory that actually gets modified directly — no new objects created each time you add something.

```java
// BAD — creates a new String object every loop iteration
String result = "";
for (int i = 0; i < 1000; i++) {
    result = result + i;   // 1000 new objects created!
}

// GOOD — modifies the SAME object every time
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append(i);   // just adds to the existing object
}
String result = sb.toString();  // convert back to String only at the end
```

---

## 6. Common StringBuilder Methods

```java
StringBuilder sb = new StringBuilder("hello");

sb.append(" world");     // sb is now "hello world"
sb.reverse();             // sb is now "dlrow olleh" — modifies the SAME object
sb.toString();             // converts back to a regular String
sb.insert(0, ">> ");       // inserts at a specific position
sb.deleteCharAt(0);        // removes character at index 0
sb.charAt(2);              // get character at index 2, just like String
sb.length();                // current length
sb.setCharAt(0, 'H');        // replace character at index 0
```

**Important:** `.reverse()` and `.append()` do NOT create a new object — they change the existing StringBuilder directly. This is the opposite behavior of String methods.

---

## 7. String vs StringBuilder — Side by Side

| | String | StringBuilder |
|---|---|---|
| Mutable? | No | Yes |
| Creates new object on change? | Yes, every time | No, modifies existing object |
| Best used for | Values that don't change often | Building/modifying text repeatedly (loops) |
| Thread-safe? | Yes (immutability makes it automatically safe) | No (use StringBuffer if thread-safety is needed) |

---

## 8. Common Mistakes People Make

- Using `==` to compare String values instead of `.equals()`.
- Concatenating Strings with `+` inside a loop instead of using StringBuilder — this is a real performance issue interviewers test for.
- Forgetting `substring(a, b)` excludes index `b` (it goes up to `b-1`).
- Thinking `.reverse()` on a StringBuilder returns a new object — it modifies the original.
- Forgetting to call `.toString()` when you need to hand the built text back as a regular String.

## 9. Full Interview Q&A

**Q1: Why is String immutable in Java?**
A: Because of the String Pool — Java shares memory for identical String values. If Strings were changeable, editing one variable could accidentally change every other variable sharing that same value. Immutability keeps the shared pool safe.

**Q2: What is the String Pool?**
A: A special area of memory where String literals (created with double quotes, not `new`) are stored. If a String with the same value already exists, Java reuses it instead of creating a duplicate.

**Q3: What's the difference between `==` and `.equals()` for Strings?**
A: `==` checks if two variables point to the exact same object in memory. `.equals()` checks if the actual text/content is the same, regardless of whether they're the same object.

**Q4: Why should you use StringBuilder instead of String concatenation inside a loop?**
A: Because String is immutable — every `+` creates a brand new object. In a loop, that means many wasted objects. StringBuilder modifies one object directly, which is much faster and uses less memory.

**Q5: Does `.reverse()` create a new StringBuilder object?**
A: No — it reverses the characters inside the existing object and returns a reference to that same object.

**Q6: What does `substring(a, b)` return?**
A: The characters from index `a` up to (but not including) index `b`.

**Q7: Is String thread-safe? Why?**
A: Yes, because it's immutable — since its value can never change, multiple threads can read it at the same time with no risk of one thread changing it while another reads it.

**Q8: What's the difference between StringBuilder and StringBuffer?**
A: They work the same way, but StringBuffer is synchronized (thread-safe, slightly slower) and StringBuilder is not synchronized (faster, used when thread-safety isn't needed — which is most of the time in DSA problems).

**Q9: If you do `String a = "test"; String b = "test";` and then `a == b`, what happens?**
A: `true` — because both were created using String literals, so both point to the same object in the String Pool.

**Q10: How do you check if two Strings have the same value, ignoring uppercase/lowercase differences?**
A: `a.equalsIgnoreCase(b)`

## 10. One-Minute Summary (say this out loud before an interview)

"String is immutable in Java because of the String Pool — shared objects for identical values, so immutability keeps that sharing safe. `==` compares memory references, `.equals()` compares actual content — always use `.equals()` for value comparison. StringBuilder exists because building Strings with `+` in a loop creates a new object every time; StringBuilder modifies one mutable object instead, making it much faster for repeated changes."
