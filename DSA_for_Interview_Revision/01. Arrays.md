# Arrays — Complete Interview Prep Notes

---

## 1. What is an Array? (in the simplest words)

An array is a **box with fixed-size compartments**, all storing the **same type** of item, sitting **right next to each other in memory**.

- "Fixed-size" → once you create it with size 5, it stays size 5 forever. You cannot add a 6th item.
- "Same type" → an `int[]` array can only hold integers, not a mix of int and String.
- "Right next to each other in memory" → this is *why* array access is instant (explained below).

Think of it like a row of lockers, numbered 0, 1, 2, 3... Each locker holds one item, and because the lockers are in a row, you can jump straight to locker number 7 without opening 0 through 6 first.

---

## 2. Declaring and Initializing Arrays

```java
// Method 1: declare with a fixed size, values default to 0 (for int)
int[] arr = new int[5];   
// arr = [0, 0, 0, 0, 0]

// Method 2: declare and fill values immediately
int[] arr2 = {10, 20, 30, 40, 50};

// Method 3: for Strings, default values are null instead of 0
String[] names = new String[3];  
// names = [null, null, null]
```

**2D Array (a grid — rows and columns):**
```java
// 3 rows, 4 columns, all zeros
int[][] grid = new int[3][4];

// 2D array with actual values
int[][] grid2 = {
    {1, 2, 3},
    {4, 5, 6},
    {7, 8, 9}
};
```
Think of a 2D array as **an array of arrays** — `grid2` is really an array containing 3 separate arrays, one per row.

---

## 3. Traversing (Looping Through) Arrays

```java
// 1D traversal
for (int i = 0; i < arr.length; i++) {
    System.out.println(arr[i]);
}

// 2D traversal — outer loop = row number, inner loop = column number
for (int i = 0; i < grid2.length; i++) {           // i = which row
    for (int j = 0; j < grid2[i].length; j++) {    // j = which column in that row
        System.out.print(grid2[i][j] + " ");
    }
    System.out.println();
}
```

**Easy way to remember:** outer loop walks down the rows, inner loop walks across the columns of that row.

## 4. Why Array Access is O(1) (Instant)

Because array elements sit in a **continuous block of memory**, the computer can calculate the exact memory address of any index using simple math:

```
address of arr[i] = starting address + (i * size of one element)
```

No searching needed — it jumps straight there. That's why it's called **O(1)**, meaning constant time no matter how big the array is.

---

## 5. Why Insertion/Deletion in the Middle is Slow (O(n))

If you want to insert a value in the middle of an array, every element after that point has to **shift over by one** to make room. If you delete, everything after has to shift back to fill the gap.

Example: inserting into position 2 of `[1, 2, 3, 4, 5]`
```
Before: [1, 2, 3, 4, 5]
Insert 99 at index 2 →
[1, 2, 99, 3, 4, 5]   ← 3, 4, 5 all had to shift right by one spot
```
In the worst case (inserting at the very start), you shift the **entire array** — that's O(n) time.

---

## 6. Arrays are Passed by Reference-Like Behavior

Even though Java is technically "pass-by-value" everywhere, arrays are objects — so what gets copied into a method is a **copy of the memory address**, not a fresh copy of the array itself.

```java
void modify(int[] a) {
    a[0] = 999;   // this changes the REAL array
}

int[] myArr = {1, 2, 3};
modify(myArr);
System.out.println(myArr[0]);  // prints 999 — original changed!
```

This is different from a plain `int` variable, where changes inside a method never affect the original.

## 7. Common Patterns Used in Array Problems (Simple Explanations)

**Two-Pointer:** Use two index variables — often one starting from the left, one from the right — and move them toward each other based on a condition. Used for things like reversing an array or finding a pair that sums to a target.

**Sliding Window:** Keep a "window" (a range of indexes) that expands or shrinks as you move through the array, instead of checking every possible sub-range from scratch. Used for problems like "find the max sum of any 3 consecutive numbers."

**Prefix Sum:** Precompute running totals so you can answer "what's the sum between index i and j?" instantly instead of adding numbers every time you're asked.

**Kadane's Algorithm:** Walk through the array keeping a running sum. If the running sum ever goes negative, reset it to 0 (since a negative running sum can only hurt future sums). Track the maximum running sum seen — that's the answer for "maximum subarray sum."

## 8. Common Mistakes People Make

- Writing `arr.length()` instead of `arr.length` — arrays use `.length` (no parentheses), Strings use `.length()` (with parentheses). This trips up almost everyone at some point.
- Off-by-one errors in loops — using `<=` instead of `<` in `for (int i = 0; i <= arr.length; i++)` causes an **ArrayIndexOutOfBoundsException**.
- Forgetting that array indexes start at **0**, not 1.
- Confusing Array (fixed size) with ArrayList (can grow/shrink).

## 9. Full Interview Q&A

**Q1: What is the time complexity of accessing an array element by index?**
A: O(1) — constant time, because the computer calculates the exact memory location directly using math, no searching required.

**Q2: Why is inserting/deleting in the middle of an array slow?**
A: Because all elements after that index must shift to make room (insertion) or fill the gap (deletion). Worst case, this touches every element — O(n).

**Q3: How is a 2D array stored in memory in Java?**
A: As an array of arrays — the outer array holds references to several inner arrays (the rows), which don't need to be the same length (called a "jagged array").

**Q4: What happens if you pass an array to a method and modify an element inside it?**
A: The original array changes, because the method receives a copy of the array's memory address, and that address still points to the same actual array in memory.

**Q5: What is the difference between an Array and an ArrayList?**
A: An Array has a fixed size decided at creation and can hold primitives directly. An ArrayList can grow or shrink dynamically but can only hold objects (not raw primitives like `int` — it needs `Integer` instead).

**Q6: What is Kadane's Algorithm used for?**
A: Finding the maximum sum of a contiguous subarray, by tracking a running sum and resetting it to zero whenever it goes negative.

**Q7: What does the two-pointer technique help with?**
A: Solving problems more efficiently (often O(n) instead of O(n²)) by moving two index pointers toward each other or in the same direction based on a condition, instead of checking every possible pair.

**Q8: What error do you get if you access an index outside the array's bounds?**
A: `ArrayIndexOutOfBoundsException`.

**Q9: Can you resize an array after creating it?**
A: No — Java arrays have a fixed size. To "resize," you have to create a new, bigger array and copy the old elements into it (this is actually what ArrayList does internally).

**Q10: What is a prefix sum array used for?**
A: Precomputing cumulative sums so that the sum of any range of the array can be found instantly (O(1)) instead of adding elements every time.

## 10. One-Minute Summary (say this out loud before an interview)

"Arrays store same-type elements in contiguous memory, giving O(1) access but O(n) insertion/deletion since elements must shift. Arrays are fixed-size and passed as a copy of their reference, so modifying elements inside a method affects the original. Common patterns: two-pointer, sliding window, prefix sum, and Kadane's algorithm for subarray problems."
