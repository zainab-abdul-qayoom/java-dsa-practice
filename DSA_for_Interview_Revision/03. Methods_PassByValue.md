# Functions & Pass-by-Value — Complete Interview Prep Notes

---

## 1. What is a Function/Method? (Simplest Explanation)

A method is a named block of code that does a specific job, which you can call (run) whenever you need it, instead of rewriting the same code repeatedly.

```java
// method definition
int add(int a, int b) {
    return a + b;
}

// calling it
int result = add(5, 3);   // result = 8
```

Parts of a method:
- **Return type** — what kind of value it gives back (`int`, `String`, `void` if nothing)
- **Name** — what you call it
- **Parameters** — the inputs it needs (inside the parentheses)
- **Body** — the actual code that runs
- **Return statement** — sends a value back to whoever called it (skip this if return type is `void`)

---

## 2. The Golden Rule: Java is ALWAYS Pass-by-Value

This is one of the single most asked interview questions in Java, and also one of the most confused. Memorize this line:

> **"Java is always pass-by-value. There is no pass-by-reference in Java."**

The confusion happens because of objects and arrays — let's break down both cases separately.

---

## 3. Case 1: Passing Primitives (int, double, char, boolean...)

When you pass a primitive into a method, Java makes a **copy of the value** and gives that copy to the method. The method works only with the copy — the original variable outside is never touched.

```java
void changeValue(int x) {
    x = 100;      // only changes the COPY
    System.out.println("Inside method: " + x);   // prints 100
}

int num = 20;
changeValue(num);
System.out.println("Outside method: " + num);    // still prints 20!
```

**Why?** Because `x` inside the method is a completely separate variable in memory from `num` outside. Changing `x` has zero effect on `num`.

**Simple analogy:** It's like giving someone a **photocopy** of a document. They can scribble all over the photocopy — your original stays clean.

---

## 4. Case 2: Passing Objects and Arrays

Objects and arrays are different because the variable doesn't hold the actual data directly — it holds a **reference** (basically a memory address, like a locker number) pointing to where the real data lives.

When you pass an object/array to a method, Java copies the **reference** — but that copied reference still points to the exact same real object in memory.

```java
void modifyArray(int[] arr) {
    arr[0] = 999;   // modifies the REAL array's content
}

int[] myArr = {1, 2, 3};
modifyArray(myArr);
System.out.println(myArr[0]);   // prints 999 — original changed!
```

**Why does this work differently from primitives?** Because `arr` (inside the method) and `myArr` (outside) are two separate variables, but they both point to the **same actual array** sitting in memory. Modifying an element through either variable changes the one real array both are looking at.

**Simple analogy:** It's like giving someone a copy of your **house address**. They didn't get your house — just the address. But if they go to that address and repaint a wall, it's still your actual house that got repainted.

---

## 5. The Trap Everyone Falls Into: Modifying vs Reassigning

This is the part that decides whether someone *actually* understands pass-by-value or just memorized the rule.

```java
void reassignArray(int[] arr) {
    arr = new int[]{9, 9, 9};   // this points 'arr' to a BRAND NEW array
}

int[] myArr = {1, 2, 3};
reassignArray(myArr);
System.out.println(myArr[0]);   // still 1 — original untouched!
```

**Why didn't this change anything?** Because `arr = new int[]{9,9,9}` makes the local variable `arr` point to a **completely new object**. It does NOT affect what `myArr` outside is pointing to. `myArr` still points to the original array — only the local copy of the reference (`arr`) was redirected elsewhere.

**The rule to remember:**
- **Modifying the contents** of what the reference points to → changes the original (`arr[0] = 999`)
- **Reassigning the reference itself to something new** → does NOT change the original (`arr = new int[]{...}`)

---

## 6. Side-by-Side Comparison Table

| Action | Does the Original Change? | Why |
|---|---|---|
| Change a primitive parameter's value | ❌ No | A brand new copy of the value was made |
| Modify an array element (`arr[0] = 5`) | ✅ Yes | Both variables point to the same real array |
| Modify an object's field (`obj.name = "x"`) | ✅ Yes | Same reason — same real object |
| Reassign the array/object parameter to something new | ❌ No | Only the local copy of the reference gets redirected |

---

## 7. Common Mistakes People Make

- Saying "Java is pass-by-reference for objects" — **wrong**. It's always pass-by-value; what's being copied is just the reference itself, not the object.
- Confusing "modifying" with "reassigning" — these behave completely differently and interviewers specifically test this.
- Thinking arrays/objects are "special" and break the pass-by-value rule — they don't; they follow it exactly, it's just that the value being copied happens to be a memory address.

## 8. Full Interview Q&A

**Q1: Is Java pass-by-value or pass-by-reference?**
A: Java is always pass-by-value. Even with objects, what's passed is a copy of the reference (memory address), not the actual object — but it's still a value being copied.

**Q2: If you pass an `int` to a method and change it inside, does the original change?**
A: No. The method receives a copy of the value; changing the copy has no effect on the original variable.

**Q3: If you pass an array to a method and change one of its elements, does the original array change?**
A: Yes. Both the original variable and the method's parameter point to the same array in memory, so modifying an element through either one affects the same real data.

**Q4: If you reassign an array parameter to a brand new array inside a method, does the original change?**
A: No. Reassigning only redirects the local copy of the reference — the original variable outside still points to its original array.

**Q5: Why does modifying an object's field work but reassigning the object itself doesn't?**
A: Because modifying goes through the reference to change the real object's data — both variables are still looking at the same object. Reassigning changes what the *local* variable points to, which doesn't touch what the *original* variable is still pointing to.

**Q6: What's a simple analogy for pass-by-value with objects?**
A: Giving someone a copy of your house address. They can go and repaint your actual house (modify) because the address points to the real house, but if they write a different address on their copy (reassign), your original address/house is untouched.

**Q7: Does Java have pointers like C++?**
A: Not in the way C++ exposes them directly — Java uses references internally, but you can't do pointer arithmetic or directly manipulate memory addresses like in C++.

---

## 9. One-Minute Summary (say this out loud before an interview)

"Java is always pass-by-value — no exceptions. For primitives, the actual value is copied, so changes inside a method don't affect the original. For objects and arrays, the reference (memory address) is copied — so modifying the contents through that reference changes the real object, but reassigning the local reference to something new does not affect what the original variable points to."
