# ArrayList — Complete Interview Prep Notes

---

## 1. What is an ArrayList? (Simplest Explanation)

An ArrayList is a **resizable array** — unlike a plain array (which has a fixed size forever), an ArrayList can grow or shrink automatically as you add or remove elements.

Internally, Java still uses a regular array behind the scenes — but when that internal array fills up, Java automatically creates a bigger array and copies everything over. You never have to do this manually; it just happens.

**Important restriction:** ArrayList can only store **objects**, not primitives directly. So you can't write `ArrayList<int>` — you have to write `ArrayList<Integer>`. Java automatically converts `int` to `Integer` and back when needed — this is called **autoboxing/unboxing**, and it happens invisibly in the background.

---

## 2. Declaring and Creating an ArrayList

```java
import java.util.ArrayList;

ArrayList<Integer> numbers = new ArrayList<>();     // empty ArrayList of Integers
ArrayList<String> names = new ArrayList<>();         // empty ArrayList of Strings

// with initial values (Java 9+)
ArrayList<Integer> nums = new ArrayList<>(List.of(1, 2, 3));
```

The `<Integer>` / `<String>` part is called a **generic type** — it tells Java what type of objects this ArrayList will hold, so you get type-safety (you can't accidentally add a String into an ArrayList of Integers).

---

## 3. Core Methods (with Why/How)

```java
ArrayList<Integer> list = new ArrayList<>();

list.add(10);                  // adds 10 to the end → [10]
list.add(20);                  // → [10, 20]
list.add(1, 15);                // inserts 15 at index 1 → [10, 15, 20]

list.get(0);                     // returns element at index 0 → 10
list.set(0, 99);                  // replaces index 0 with 99 → [99, 15, 20]

list.remove(1);                    // removes element AT INDEX 1 → [99, 20]
list.remove(Integer.valueOf(20));    // removes the VALUE 20 (not index 20!) → [99]

list.size();                          // number of elements currently in the list
list.isEmpty();                        // true if size == 0
list.contains(99);                      // true/false — checks if a value exists
list.indexOf(99);                        // returns the index of value 99, or -1 if not found
list.clear();                             // removes everything

for (int num : list) {                      // for-each loop
    System.out.println(num);
}

for (int i = 0; i < list.size(); i++) {        // index-based loop
    System.out.println(list.get(i));
}
```

## 4. The `remove()` Trap — One of the Most Common Mistakes

`remove()` is overloaded (has two versions), and this trips up almost everyone at some point:

```java
ArrayList<Integer> list = new ArrayList<>();
list.add(20);
list.add(30);
list.add(40);

list.remove(1);                  // removes by INDEX → removes 30 (index 1), leaves [20, 40]
list.remove(Integer.valueOf(30));  // removes by VALUE → searches for 30 and removes it
```

**Why the confusion happens:** `list.remove(20)` looks like it should remove the value `20`, but since `20` is an `int` literal, Java treats it as an **index**, not a value. To remove by value, you must explicitly wrap it: `Integer.valueOf(20)`, which forces Java to treat it as an object (value) instead of a primitive index.

---

## 5. ArrayList vs Array — Side by Side

| | Array | ArrayList |
|---|---|---|
| Size | Fixed at creation | Grows/shrinks automatically |
| Stores primitives directly? | Yes (`int[]`) | No — needs wrapper classes (`Integer`, not `int`) |
| Syntax to get length | `.length` (no parentheses) | `.size()` (with parentheses) |
| Performance | Slightly faster (no overhead) | Slightly slower (resizing overhead, boxing/unboxing) |
| Best for | Fixed-size data, performance-critical code | Data where size changes, general-purpose use |

---

## 6. How Resizing Actually Works (Why ArrayList Can Grow)

Internally, an ArrayList holds a regular array with some starting capacity (commonly 10). When you try to add an element and the internal array is already full, Java:
1. Creates a brand new, bigger array (typically 1.5x the old size)
2. Copies every existing element into the new array
3. Adds your new element
4. The old array is discarded (cleaned up by garbage collection)

**Why this matters for interviews:** most `add()` operations are fast (O(1)), but occasionally — when resizing is triggered — a single `add()` call becomes O(n), since it has to copy everything. Averaged out over many additions, this still works out to O(1) "amortized" time, which is a common interview talking point.

---

## 7. Common Mistakes People Make

- Confusing `remove(index)` with `remove(value)` — covered above, the #1 ArrayList mistake.
- Trying to write `ArrayList<int>` instead of `ArrayList<Integer>` — primitives aren't allowed as generic types.
- Using `.length` instead of `.size()` — arrays use `.length`, ArrayLists use `.size()`.
- Modifying an ArrayList (adding/removing) while iterating over it with a for-each loop — this throws a `ConcurrentModificationException`. Use an `Iterator` if you need to remove elements while looping.

## 8. Full Interview Q&A

**Q1: What is the main difference between an Array and an ArrayList?**
A: An Array has a fixed size decided at creation, while an ArrayList can grow or shrink dynamically. Arrays can hold primitives directly; ArrayLists can only hold objects (using wrapper classes like Integer).

**Q2: How does ArrayList grow internally when it runs out of space?**
A: It creates a new, larger internal array (typically 1.5x the previous capacity), copies all existing elements into it, then continues adding new elements. This happens automatically and is invisible to the programmer.

**Q3: What's the time complexity of `add()` on an ArrayList?**
A: O(1) amortized — most additions are instant, but occasionally a resize is triggered which is O(n), averaging out to constant time overall.

**Q4: What's the time complexity of `get(index)`?**
A: O(1) — since the underlying structure is still an array, accessing by index is direct and instant.

**Q5: What's the time complexity of removing an element from the middle of an ArrayList?**
A: O(n) — all elements after the removed index must shift left by one to fill the gap.

**Q6: What is the difference between `list.remove(2)` and `list.remove(Integer.valueOf(2))`?**
A: `remove(2)` removes the element **at index 2**. `remove(Integer.valueOf(2))` removes the element whose **value is 2**, wherever it is in the list.

**Q7: Why can't you create an `ArrayList<int>`?**
A: Generics in Java only work with objects, not primitives. You must use the wrapper class `Integer` instead — Java then automatically converts between `int` and `Integer` behind the scenes (autoboxing/unboxing).

**Q8: What happens if you try to modify an ArrayList while looping through it with a for-each loop?**
A: It throws a `ConcurrentModificationException`. To safely remove elements while iterating, use an explicit `Iterator` and its `.remove()` method instead.

## 9. One-Minute Summary (say this out loud before an interview)

"ArrayList is a resizable array — it grows automatically by creating a bigger internal array and copying elements over when it runs out of space, giving amortized O(1) add time but O(n) time for insertion/removal in the middle. Unlike arrays, it can only store objects, not primitives directly, requiring wrapper classes like Integer through autoboxing. The most common trap is `remove(index)` vs `remove(value)` — an int argument is treated as an index unless explicitly wrapped with `Integer.valueOf()`."
